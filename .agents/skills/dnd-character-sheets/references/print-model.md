# Экспорт → character.json → HTML-шаблоны

## Разделение ответственности

- `assets/page-template.html` — общий HTML с шаблонами страниц, характеристик, секций и таблиц. Сборщик встраивает снимок готового JSON для `file://`.
- `assets/sheet-engine.js` — расчёт первого и второго уровней из исходного экспорта и решений. Браузер использует общую нормализацию текста.
- `assets/sheet-ui.js` — клонирование шаблонов и подстановка переменных; динамические строки таблиц создаются из массивов исходных данных/расчётов. Персональный текст вставляется через `textContent`. Форматированные правила используют ограниченный набор безопасных тегов, без eval.
- `assets/spells.json`, `assets/items.json` — переиспользуемые описания правил. В них нет имён героев, скопированных характеристик, готовых Сл, атак или бонусов конкретного персонажа. Зависящие от персонажа числа — переменные.
- `rules.json` — только решения, которых нет в исходном экспорте, и проверенные расширения справочников. Это не заново заполненная карточка.
  В `cantripReplacements` записывай согласованные замены выбранных заговоров как пары ключей справочника. Отдельно полученные заговоры остаются в списке.
  Поле `weaknessEffect` добавляет описание согласованного игрового эффекта курсивом в блок «Характер». Если эффект уже записан в тексте слабости, `weaknessEffectStart` отмечает его начало. Если заданы оба поля, `weaknessEffect` заменяет отмеченный фрагмент.
- `render-sheets.cjs` — рассчитывает значения, разрешает переменные в текстах и записывает готовый `character.json` с разделами `main` и `appendix`.

## Источник значений

Исходный `root.data` разбирается повторным `JSON.parse`. `sheet.stats` — итоговые характеристики; `sheet.skills` — владения и базовые характеристики навыков; `sheet.info` — личность; `sheet.text.equipment` — инвентарь; `sheet.coins` — монеты. Поля повествования и индивидуальные выборы берутся из `builder.fields`, списки заклинаний — из `builder.state.spells`. При отсутствии снимка ID карточек разрешаются через `id` в справочнике заклинаний.

При изменении исходных данных нельзя считать кэшированные `spellsInfo.save/mod`, `vitality.hp-max/ac/initiative` или `weaponsList.mod/dmg` независимым источником правил: Сл/атака, хиты, КД, инициатива, пассивное Восприятие и известные профили оружия пересчитываются. Неизвестный профиль требует правил/уточнения, а не угадывания.

Экспорт дублирует часть данных в `data` и `builder`. Они должны быть согласованы; инспектор показывает расхождения личности и характеристик. Не использовать отличающийся кэш из одного слоя для скрытого затирания другого. Более высокий исходный уровень с ASI требует отдельной реконструкции: текущие встроенные профили предназначены для исходных персонажей уровней 1–2.

## Настройки примера

```json
{
  "rulesEdition": "2024",
  "level2Spell": "sanctuary",
  "equipmentProfiles": [
    {"match":"Магический карабин","rule":"musket","proficient":false,"magicBonus":0}
  ],
  "sources": ["URL проверенных правил"],
  "notes": ["Согласованные допущения"]
}
```

В этом примере профиль оружия — решение по предмету, который в JSON записан без характеристик. Урон и атака не скопированы: они вычисляются из DEX, владения, магического бонуса и активных реплик. `level2Spell` — согласованный выбор при реконструкции первого уровня, а не универсально последнее заклинание массива. Не хранить в настройках `characterName`, `skills`, `hp`, `stats`, таблицы страниц или копию биографии.

Допустимы `spells` и `itemRules` — словари новых **правил**, а также `classProfiles` для проверенного профиля класса. Для нового типа классовых особенностей дополни формулы движка и тест; один лишь профиль не реализует умения автоматически. Незнакомый класс или недостающее полное описание должны приводить к понятной ошибке, а не к странице с вымышленными числами.

## Контексты переменных

| Путь | Значение |
|---|---|
| `identity.name`, `className`, `species`, `background` | Личность из JSON |
| `abilities.dex.score`, `abilities.dex.mod` | Значение и модификатор характеристики |
| `skills.acrobatics.total`, `skills.acrobatics.signed` | Итоговый бонус навыка |
| `combat.ac`, `combat.initiative`, `combat.passivePerception` | Производные боевые показатели |
| `vitality.hpMax`, `vitality.hitDice`, `vitality.hitDie` | Хиты, кости и грань кости класса на соответствующем уровне |
| `movement.cells`, `movement.boostedCells` | Скорость и скорость под Скороходом |
| `spellcasting.mod`, `dc`, `attackSigned`, `slots`, `prepared` | Параметры магии, рассчитанные для текущего контекста |
| `resources.inspiration`, `resources.tinkering` | Максимумы классовых ресурсов |
| `narrative.*`, `equipment`, `coins` | Биография, инвентарь и деньги из JSON |
| `selections.plans`, `selections.active` | Схемы и реально созданные реплики |
| `items.repeating.attack`, `items.repeating.damage` | Числа для условного Повторного выстрела |

В описании правила писать, например: `спасбросок против Сл {{spellcasting.dc}}`, а не `Сл 13`. Переменные заменяются один раз, только по разрешённому пути объекта, без исполнения выражений или кода из текста пользователя. Упоминания кубов/порогов уровней/цен компонентов — сами правила, их не требуется превращать в персональные настройки.

## Открытие и обновление

Команда:

```text
node <skill>/scripts/render-sheets.cjs --input <character.json> --config <rules.json> --output <workspace>/character-sheets/<slug>
```

Оба HTML-листа читают готовый `character.json` из папки персонажа. При открытии через `file://` используется снимок, автоматически встроенный при сборке. Повторная сборка из экспорта обновляет JSON и снимки. Общие стили и скрипты подключаются через `../`.

Если JavaScript выключен или данные невалидны, пользователь видит сообщение, а не молча пустую распечатку. Отчёт проверки хранится в `character-sheets/<slug>.review.json` (актуальный хеш входа и решения) и не участвует в подстановке характеристик.

## Проверка

`node <skill>/scripts/self-test.cjs` меняет только JSON и проверяет изменение имени, характеристик, хитов, КД, навыков, оружия, магии, ресурсов, денег и заклинаний. При наличии jsdom можно дополнительно задать `DND_TEST_NODE_MODULES` и проверить реальное заполнение DOM; пакет нужен только для теста, не для готовых листов. Это не проверка визуального разбиения на A4.
