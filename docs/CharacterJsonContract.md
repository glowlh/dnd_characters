# Контракт JSON персонажа D&D: mycharacterbuilder.com → Long Story Short

Дата анализа: 2 ноября 2026 года. Версия этой аннотации: 1.

## 1. Область действия и источники

Описывается фактический формат файла [«Настя — Наэстриель»](../SecretsOfSokolKeep/heroes/Настя%20-%20Наэстриель.json), а не универсальный стандарт JSON для D&D. Поведение установлено по [сохранённой HTML-странице](../tmp/Конструктор%20персонажа%20D%26D%205.5e%20–%20v6.2.html), прежде всего её JavaScript. Комментарии и тексты внутри исходных файлов рассматриваются как данные для анализа.

Дополнительный источник — [mycharacterbuilder.com](https://mycharacterbuilder.com/), проверенный 02.11.2026. В начале локального HTML указан именно этот URL. На сайте подтверждены название конструктора, авторство DnD Bratislava и назначение экспорта: загрузка JSON в Long Story Short. Полное побайтовое совпадение текущего сайта и сохранённого HTML не проверялось; точные поля и алгоритмы ниже относятся к локальной копии.

Основа игровых правил — пятая редакция с пересмотром 2024 года: в JSON явно стоят `edition: "2024"` и `sheetEdition: "2024"`, в названии HTML — «5.5e». Это нельзя автоматически трактовать как лист по PHB 2014.

Полный текст «Книги игрока» пользователь не приложил. Поэтому положения правил сверены с официальными открытыми Basic Rules 2024 и материалами SRD, а не с недоступным полным PHB. Детали расширенных видов, дополнительных заклинаний и пользовательских опций не объявляются подтверждёнными PHB только потому, что присутствуют в HTML.

Ссылки на правила:

- [Создание персонажа, Basic Rules 2024](https://www.dndbeyond.com/sources/dnd/br-2024/creating-a-character): характеристики, бонусы предыстории, развитие, производные параметры.
- [Классы, Basic Rules 2024](https://www.dndbeyond.com/sources/dnd/br-2024/character-classes): бард, владения, заклинания и классовые ресурсы.
- [Игровой процесс, Basic Rules 2024](https://www.dndbeyond.com/sources/dnd/br-2024/playing-the-game): проверки, владение, бой, урон и лечение.
- [Происхождение, Basic Rules 2024](https://www.dndbeyond.com/sources/dnd/br-2024/character-origins): структура вида и предыстории; открытый набор опций ограничен.
- [Официальный SRD](https://www.dndbeyond.com/srd): открытые системные правила и версии документа.
- [Характеристики, Basic Rules 2014](https://www.dndbeyond.com/sources/dnd/basic-rules-2014/using-ability-scores): сопоставление с прежней редакцией; не основание заменять механику 2024.

Обозначения: `root` — результат первого разбора файла, `sheet` — результат `JSON.parse(root.data)`, `builder` — `root.dndBratislavaBuilder`. Пути `sheet.*` существуют внутри сериализованной строки, а не непосредственно на верхнем уровне файла.

## 2. Устройство формата и источник истины

В одном файле сохранены три слоя:

1. **Оболочка Long Story Short (LSS):** версия, режим карточек, ссылки на базу заклинаний, служебные параметры.
2. **Снимок конструктора:** `dndBratislavaBuilder.fields` и `.state`, из которых HTML восстанавливает выборы пользователя.
3. **Лист персонажа:** `data`, строка с ещё одним JSON-объектом, с итоговыми характеристиками, оружием, текстами и ресурсами.

```javascript
const root = JSON.parse(fileText);
if (typeof root.data !== "string") throw new Error("Ожидается строка data");
const sheet = JSON.parse(root.data);
// После редактирования листа:
root.data = JSON.stringify(sheet);
const resultText = JSON.stringify(root, null, 2);
```

`data` нельзя заменять объектом при записи этого профиля экспорта. Старый импорт конструктора допускает объект в `data`, но сам экспорт всегда создаёт строку.

**Приоритет импорта HTML:** `dndBratislavaBuilder` → альтернативная анкета `schema: "dnd5e2024-character-questionnaire-v1"` → частичное восстановление из `data` старого LSS-файла. При наличии снимка конструктора HTML не объединяет его с листом. При старом импорте восстанавливаются только имя, игрок, уровень, вид, класс, предыстория и подкласс; характеристики, заклинания и текущие ресурсы таким способом не восстанавливаются полностью.

**Повторный экспорт:** `prepareExportFromCurrentForm()` пересчитывает форму и вызывает `collectLss()`. Это генерация нового листа: текущие хиты становятся максимальными, временные хиты и смерти обнуляются, ячейки становятся неизрасходованными, часть идентификаторов и дата создания генерируются заново. Это не гарантированное сохранение состояния игрового сеанса.

Для продолжения редактирования в HTML источником истины является снимок конструктора; для чтения уже экспортированного листа — `sheet`. Если изменить только `sheet`, следующий экспорт из HTML может затереть изменения. Правки следует согласовывать в обоих слоях или делать через сам конструктор.

## 3. Типы, пустые значения и обязательность

- JSON кодируется UTF-8; имена и тексты могут быть кириллическими.
- `string`, `number`, `boolean`, `object`, `array` — реальные JSON-типы; строки `"2"` и числа `2` не взаимозаменяемы.
- HTML-поля по умолчанию сериализуются строками, checkbox — boolean. Расчётные параметры в `state` и `sheet` преимущественно числовые.
- `""` означает отсутствие выбора/текста; `[]` — пустой список; `{}` — пустой словарь. Их нельзя безусловно заменять `null`.
- Отсутствие `sheet.skills.<key>.isProf` означает, что владение и компетентность не установлены; это не ошибка и не пропущенный итоговый бонус.
- Ниже «постоянное поле» означает, что оно всегда создаётся рассматриваемым экспортёром. Это не доказательство, что внешний сервис требует его при любом импорте: серверная схема LSS не исследована.
- Рекомендуемый читатель сохраняет неизвестные поля. Экспортёр HTML этого не гарантирует: он собирает объект заново из известной формы.

## 4. Верхний уровень `root`

Все строки таблицы — постоянные поля `collectLss()`.

| Путь | Тип / значение в профиле | Назначение |
|---|---|---|
| `jsonType` | string, `"character"` | Тип экспортируемого документа |
| `version` | string, `"2"` | Версия оболочки LSS; не уровень и не редакция D&D |
| `edition`, `sheetEdition` | string, `"2024"` | Редакция правил и листа |
| `tags`, `rooms` | array, `[]` | Служебные списки; непустая структура данным экспортом не определена |
| `disabledBlocks` | object | Настройки скрытых/отключённых блоков интерфейса |
| `disabledBlocks.info-left`, `info-right`, `subinfo-left`, `subinfo-right`, `notes-left`, `notes-right` | array, `[]` | Шесть областей; тип элементов непустого списка не установлен |
| `disabledBlocks._id` | string | Генерируемый 24-символьный hex-подобный ID; игровой семантики нет |
| `spells` | object | Карточки заклинаний, см. ниже |
| `linkAccess` | string, `"none"` | Служебный режим доступа по ссылке; не настройка правил |
| `dndBratislavaBuilder` | object | Снимок формы и состояния |
| `data` | string | Вложенный сериализованный лист |
| `lastWriterSessionId` | string | Генерируемый ID сессии записи; не ID персонажа |

`root.spells`:

| Поле | Тип | Смысл |
|---|---|---|
| `mode` | string, `"cards"` | Отображение карточками |
| `prepared` | string[] | Уникальные ID карточек: объединение заговоров, всегда подготовленных, подготовленных и магии черт происхождения |
| `book` | string[] | ID карточек книги заклинаний |
| `granted`, `slotless` | array, `[]` | Резервные списки; этот экспортёр оставляет пустыми |
| `edition` | string, `"2024"` | Редакция карточек |

Название `prepared` здесь шире игрового понятия «подготовленные заклинания»: в образце это **семь карточек = два заговора + пять заклинаний 1-го уровня**, а не семь подготовленных заклинаний 1-го уровня. ID — ключи внешнего каталога LSS, не названия и не UUID; нельзя выводить по ним уровень заклинания без каталога.

## 5. Снимок `builder`

### 5.1. Метаданные

| Поле | Тип / пример | Смысл |
|---|---|---|
| `schemaVersion` | number, `1` | Версия снимка конструктора |
| `builderVersion` | string, `"5.50"` | Вшитая версия экспортёра |
| `fields` | object | Словарь `DOM-id → значение` |
| `state` | object | Выборы и результаты, не сводящиеся к одному полю формы |

`builderVersion: "5.50"` присутствует и в JSON, и в коде страницы с названием v6.2. Следовательно, нельзя проверять совместимость сравнением этих двух строк. Версия листа `"2"`, схема снимка `1`, редакция `"2024"` и версия интерфейса — разные оси версионирования.

### 5.3. `builder.state`

| Поле | Тип | Назначение / образец |
|---|---|---|
| `abilityApplied` | boolean | `true`: итоговые характеристики рассчитаны |
| `baseAbilities` | object, шесть number | Исходные `8,14,13,10,12,15` |
| `finalAbilities` | object, шесть number | Итоговые `8,15,15,10,12,15` |
| `backgroundBonuses` | object, шесть number | Прибавки: `dex:1`, `con:2`, остальные `0` |
| `equipmentPackage` | string | `"Набор А"`, ключ выбранного пакета |
| `spellClass` | string | `"Бард"`, класс магии |
| `spells` | object | `cantrips`, `prepared`, `spellbook`, `bardDiscoveries`: массивы строковых ключей каталога конструктора |
| `originMagic` | object | Объекты `background` и `human`: `{source:string, ability:string, cantrips:string[], spell:string}`; в образце пустые строки/массивы |
| `levelFeats` | object | Словарь `русское имя класса → строка уровня → {name:string, choices:object}` |
| `wildShapeForms` | string[] | Выбранные названия форм дикого облика; у барда `[]` |
| `customResources` | object[] | Пользовательские счётчики; в образце `[]` |
| `customBonuses` | object[] | Пользовательские модификаторы; в образце `[]` |
| `customWeapons` | object[] | Пользовательское оружие; в образце `[]` |
| `subclassSelections` | object | Выбор подкласса по имени класса; в образце `{}` |
| `activeSubclassClass` | string | `"Бард"`; при восстановлении код устанавливает по `fields.className` |

`levelFeats` содержит заготовки для 13 классов, включая Изобретателя. Обычно ключи уровней `"4"`, `"8"`, `"12"`, `"16"`; у Плута дополнительно `"10"`, у Воина `"6"` и `"14"`. Пустое `name` не означает полученную черту. Наличие заготовок других классов не означает мультикласс. Эпические дары 19-го уровня нельзя считать отсутствующими в правилах по отсутствию такого ключа в образце.

Расширения, подтверждённые кодом, но пустые в образце:

```text
customResources[] = {uid:string, name:string, current:number, max:number,
                     recovery:"long-rest"|"short-rest"|"manual",
                     location:"traits"|"features"|"feats"|"equipment", notes:string}
customBonuses[]   = {uid:string, label:string, target:string, expr:string}
customWeapons[]   = {uid:string, name:string, damage:string, ability:string,
                     proficient:boolean, damageType:string, notes:string}
```

Цели бонусов в этом HTML: `initiative`, `stat.<ability>.score`, `save.<ability>`, `skill.<skill-key>`. Синтаксис произвольных выражений `expr` движка LSS этим кодом полностью не определён; нельзя исполнять строку как JavaScript. `damage` — текст, например `1к8+3`; конструктор не выводит его автоматически из указанной характеристики пользовательского оружия.

## 6. Вложенный лист `sheet`

### 6.1. Личность и описание

| Путь | Тип | Смысл |
|---|---|---|
| `jsonType`, `template` | string | `"character"`, `"default"` |
| `name.value` | string | Имя |
| `info.charClass`, `charSubclass`, `background`, `playerName`, `race`, `alignment`, `experience` | `{name:string,value:string}` | Класс, подкласс, предыстория, игрок, вид, мировоззрение, опыт; последние три описательных/учётных поля могут быть пусты |
| `info.level` | `{name:"level",value:number}` | Уровень: `2` |
| `info.size.value` | string | `medium` в образце; экспортёр также выдаёт `small`, `large` |
| `subInfo.age`, `height`, `weight`, `eyes`, `skin`, `hair` | `{name:string,value:string}` | Возраст, рост, вес, глаза, кожа, волосы; все пусты в образце |
| `createdAt` | string, ISO 8601 UTC | В образце `2026-11-01T18:42:20.068Z`; время генерации листа, не гарантированная дата первого создания героя |

### 6.2. Характеристики, спасброски и навыки

Коды характеристик: `str` — Сила, `dex` — Ловкость, `con` — Телосложение, `int` — Интеллект, `wis` — Мудрость, `cha` — Харизма.

- `stats.<ability> = {name:<ability>, score:number}` — **значение** характеристики, не модификатор.
- `proficiency:number = 2` — бонус владения.
- `saves.<ability> = {name:<ability>, isProf:boolean}` — владение спасброском; итоговый бонус не хранится здесь. У барда `dex:true`, `cha:true`.
- `skills.<key> = {baseStat:<ability>, name:<key>, isProf?:1|2}`: `1` — владение, `2` — компетентность, отсутствие — ни того ни другого. Это не boolean и не готовый бонус.

Базовые формулы: `modifier = floor((score − 10) / 2)`; для обычного развития 1–20 `PB = 2 + floor((level − 1) / 4)`. Проверка навыка использует модификатор характеристики и PB при владении либо 2×PB при компетентности; особые способности учитываются отдельно. Основание: [характеристики и проверки 2024](https://www.dndbeyond.com/sources/dnd/br-2024/playing-the-game).

Все 18 навыков образца (бонусы рассчитаны для 2024 с «Мастером на все руки» барда 2-го уровня):

| JSON-ключ | Навык | База | `isProf` | Итоговый бонус |
|---|---|---|---|---|
| `acrobatics` | Акробатика | dex | 1 | +4 |
| `investigation` | Анализ | int | 1 | +2 |
| `athletics` | Атлетика | str | 1 | +1 |
| `perception` | Восприятие | wis | 1 | +3 |
| `survival` | Выживание | wis | 2 | +5 |
| `performance` | Выступление | cha | отсутствует | +3 |
| `intimidation` | Запугивание | cha | отсутствует | +3 |
| `history` | История | int | отсутствует | +1 |
| `sleight of hand` | Ловкость рук | dex | 1 | +4 |
| `arcana` | Магия | int | отсутствует | +1 |
| `medicine` | Медицина | wis | отсутствует | +2 |
| `deception` | Обман | cha | 1 | +4 |
| `nature` | Природа | int | отсутствует | +1 |
| `insight` | Проницательность | wis | 1 | +3 |
| `religion` | Религия | int | отсутствует | +1 |
| `stealth` | Скрытность | dex | 1 | +4 |
| `persuasion` | Убеждение | cha | 2 | +6 |
| `animal handling` | Уход за животными | wis | отсутствует | +2 |

Пробелы внутри `sleight of hand` и `animal handling` — часть ключей. Не заменять их подчёркиваниями.

Владений десять: 2 от предыстории + 2 от вида + 3 от класса + 3 от черты. Два из них улучшены до компетентности. Это согласуется с выборами в снимке. «Мастер на все руки» добавляет половину PB с округлением вниз к подходящим проверкам навыков без владения; `lssAllSkills()` не кодирует эту половину в `isProf`, а `sheet.bonuses` в образце пуст. Поэтому отдельный потребитель должен учитывать способность сам; нельзя считать, что она уже численно отражена в этих полях. По [правилам барда 2024](https://www.dndbeyond.com/sources/dnd/br-2024/character-classes) эта способность не распространяется на инициативу просто как на проверку Ловкости.

### 6.3. Жизненные и боевые параметры `vitality`

| Поле | Тип / образец | Семантика |
|---|---|---|
| `hp-dice-current.value` | number, `2` | Текущее количество костей хитов; экспортёр инициализирует уровнем |
| `hp-dice-multi` | object, `{}` | Резерв мультиклассовых костей; непустой формат не установлен |
| `hp-max-con-bonus.value` | number, `0` | Служебная дополнительная величина; не модификатор Телосложения. CON уже учтено в `hp-max` |
| `darkvision.value` | number, `0` | Дальность тёмного зрения в футах; код извлекает её из текста вида |
| `hp-current.value`, `hp-max.value` | number, `17` | Текущие и максимальные хиты |
| `hp-temp.value` | number, `0` | Временные хиты |
| `isDying` | boolean, `false` | Служебное состояние умирания |
| `deathFails`, `deathSuccesses` | number, `0` | Счётчики спасбросков от смерти |
| `speed.value` | **string**, `"30"` | Скорость в футах; не число в данном формате |
| `initiative.value` | number, `2` | Базовый рассчитанный бонус инициативы |
| `shield.value` | boolean, `false` | Щит не экипирован; HTML всегда экспортирует false |
| `ac.value` | number, `13` | Класс доспеха (КД) |
| `hit-die.value` | string, `"d8"` | Тип кости хитов; латинская `d` |

Расчёт примера: CON 15 даёт +2; бард с d8 получает `8+2 + 5+2 = 17` хитов при фиксированном приросте после 1-го уровня. Кожаный доспех даёт `11 + DEX(+2) = 13` КД; инициатива +2. Это соответствует выбранным данным. Код оценивает доспех по тексту снаряжения; наличие вещи в списке не является универсальным доказательством её ношения. Автоматический выбор экипировки требует отдельной проверки для других персонажей.

### 6.4. Магия

| Путь | Тип / пример | Смысл |
|---|---|---|
| `spellsInfo.base` | `{name:"base",value:"Харизма",code:"cha"}` | Заклинательная характеристика |
| `spellsInfo.save` | `{name:"save",value:12}` | Сложность спасброска против заклинаний |
| `spellsInfo.mod` | `{name:"mod",value:4}` | **Бонус атаки заклинанием**, а не чистый модификатор Харизмы |
| `spellsInfo.available.classes` | string[], `["bard"]` | Коды списков заклинаний |
| `spells.slots-1` | `{value:3,filled:0}` | Максимум ячеек 1-го уровня и начальный счётчик; экспортёр всегда ставит `filled:0` |
| `spells.level-1-slot-0` … `level-1-slot-2` | `{isChecked:false}` | Неотмеченные ячейки, индексация с нуля |
| `spellsPact` | object, `{}` | Отдельные ячейки магии договора; для соответствующего класса код выдаёт `{"slots-1":{value:<количество>}}` |
| `casterClass.value` | string, `"Бард"` | Класс заклинателя; поле условное, добавляется при наличии классовой магии |

Для обычных ячеек шаблоны ключей: `slots-<уровень>` и `level-<уровень>-slot-<индекс>`. `filled` и `isChecked` создаются обнулёнными; точную синхронизацию этих двух представлений в работающем LSS данный HTML не устанавливает.

Числа примера: Сл `8 + PB(2) + CHA(2) = 12`; атака `PB(2) + CHA(2) = +4`. [Официальные формулы создания персонажа](https://www.dndbeyond.com/sources/dnd/br-2024/creating-a-character). Бард 2-го уровня по [таблице класса 2024](https://www.dndbeyond.com/sources/dnd/br-2024/character-classes) имеет 2 заговора, 5 подготовленных заклинаний и 3 ячейки 1-го уровня — количества в образце совпадают.

Связь ключей снимка с внешними ID установлена по `SPELL_CATALOG_SRD` в HTML; название этой переменной само по себе не доказывает происхождение каждого заклинания из SRD:

| Массив `builder.state.spells` | Ключ | Название в HTML | ID в `root.spells.prepared` |
|---|---|---|---|
| `cantrips` | `friends` | Дружба | `6a130a8fcc5574d767281b46` |
| `cantrips` | `animate-skull` | Оживленный череп | `6a4e9ce4cb7ab61dc8777c23` |
| `prepared` | `thunderwave` | Волна грома | `698197b8a5dc6923c7028b3c` |
| `prepared` | `heroism` | Героизм | `698197b7a5dc6923c7028b20` |
| `prepared` | `dissonant-whispers` | Диссонирующий шёпот | `698197b9a5dc6923c7028b5f` |
| `prepared` | `unseen-servant` | Невидимый слуга | `698197cca5dc6923c7028ddc` |
| `prepared` | `command` | Приказ | `698197dda5dc6923c7029021` |

`spellbook` и `bardDiscoveries` пусты. Для заклинаний без ID экспортёр добавляет текстовые блоки `sheet.text.spells-level-0` … `spells-level-9`, а для неразрешённых заклинаний книги — `sheet.text.spellbook`. В данном образце таких блоков нет. Отсутствие текстов заклинаний в `sheet.text` не означает отсутствия магии: полные карточки разрешаются внешним каталогом.

### 6.5. Оружие, владения, настройка и деньги

`weaponsList` — массив строк атак. В образце одна строка кинжала, хотя снаряжение содержит два кинжала: строки не являются учётом количества предметов.

```text
weaponsList[] = {id:string, name:{value:string}, mod:{value:string},
                 dmg:{value:string}, ability:<ability>, isProf:boolean,
                 dmgType?:{value:string}, notes?:{value:string}}
```

Кинжал: `mod.value:"+4"` = DEX + PB; `dmg.value:"1к4+2"` = кость урона + DEX; `ability:"dex"`, `isProf:true`, `dmgType.value:"колющ."`. Кириллическая `к` в уроне и латинская `d` в кости хитов — фактические разные текстовые соглашения. Автоматическое оружие HTML всегда маркирует как освоенное и прибавляет PB; для иных наборов это поведение нельзя принимать за независимую проверку владения по правилам.

`prof` — структурированные владения экипировкой. В образце `armor-light.value:true`, `weapon-simple.value:true`; `armor-label.value:true` — служебный флаг блока. Экспортёр также умеет выдавать `armor-medium`, `armor-heavy`, `weapon-martial`. Это не список инструментов и языков: они находятся в `text.prof`.

`attunementsList[] = {id:string, checked:boolean, value:string}` — строки настройки на магические предметы. Единственная пустая строка с `checked:false` — заготовка интерфейса, а не настроенный предмет. Заполненные строки экспортируются с `checked:true`; форма читает до трёх полей `attunement0..2`.

`coins` содержит `cp`, `sp`, `ep`, `gp`, `pp`, `total`, каждое как `{value:number}`. Это медные, серебряные, электрумовые, золотые, платиновые монеты и итог в золотом эквиваленте. Код считает `total = round((cp/100 + sp/10 + ep/2 + gp + pp*10) * 100) / 100`. В образце только 34 зм, поэтому `gp.value = total.value = 34`. Это итог экспорта; история покупок и происхождение всей суммы в JSON не зафиксированы.

### 6.6. Форматированные тексты `text`

Каждый блок имеет структуру:

```json
{
  "value": {
    "id": "hover-toolbar-example-...",
    "data": {
      "type": "doc",
      "content": [{"type": "paragraph", "content": [{"type": "text", "text": "Текст"}]}]
    }
  },
  "size": 9
}
```

Возможен `customLabel:string`, переопределяющий заголовок. `size` — параметр отображения, не размер существа. Пустой абзац может быть `{type:"paragraph"}` без `content`. У текстовых узлов встречается `marks:[{type:"bold"},{type:"italic"}]`. Это дерево форматированного документа, не HTML-строка и не обычная строка. Неизвестные типы узлов следует сохранять.

| Ключ | Фактическое назначение в экспортёре |
|---|---|
| `prof` | Инструменты и языки |
| `equipment` | Снаряжение класса и предыстории |
| `features`, `items` | Дополнительные способности и умения; в `features` — «Мастер на все руки» |
| `attacks` | Дополнительные тексты атак; пуст в образце |
| `traits` | Классовые черты и ссылки на счётчики, в примере Бардовское вдохновение |
| `personality`, `ideals`, `flaws`, `bonds` | Стандартные блоки характера; в образце пусты |
| `allies` | **Способности вида**, заголовок «СПОСОБНОСТИ РАСЫ»; не союзники |
| `quests` | `fields.characterReason`, заголовок «Цели и квесты» |
| `feats` | Черты происхождения и уровня; в образце «Одарённый» |
| `background` | `fields.characterPast`, повествовательное прошлое; механическая предыстория — в `info.background` |
| `appearance` | `fields.appearance` |
| `notes-1` | `fields.characterHook`, фишка |
| `notes-2` | `fields.characterWeakness`, слабость |
| `notes-3` | Дополнительные сведения о внешности/особенностях; пуст в образце |

Нельзя восстанавливать смысл только по английскому ключу: например, слабость персонажа записана в `notes-2`, а `flaws` пуст.

### 6.7. Ресурсы и остальные служебные поля

`resources` — словарь `resourceId → объект`. ID должен совпадать с `.id` самого объекта и ссылкой в дереве текста:

```text
text.<block>.value.data.content[] =
  {type:"resource", attrs:{id:<resourceId>, textName:<location>}}

resources[resourceId] = {
  id:string, name:string, current:number, resolvedMax:number, location:string,
  notes:string, notesVisibility:boolean, maxExpr:string,
  isLongRest?:boolean, isShortRest?:boolean, icon?:string
}
```

В образце ресурс `resource-1793558540059-ac90b1`: Бардовское вдохновение, `current:2`, `resolvedMax:2`, `maxExpr:"2"`, `location:"traits"`, `isLongRest:true`, `icon:"long-rest"`. Текстовый блок `traits` содержит ссылку с тем же ID. Число использований соответствует CHA +2; кость к6 описана текстом. Восстановление после долгого отдыха на этом уровне соответствует [барду 2024](https://www.dndbeyond.com/sources/dnd/br-2024/character-classes). Пустой `customResources` не означает отсутствия ресурсов: автоматические ресурсы генерируются из класса и уровня.

Код ограничивает экспортируемое текущее значение диапазоном 0…max. Для короткого отдыха ставит `isShortRest:true` и `icon:"short-rest"`; для ручного восстановления не ставит флаг отдыха. `maxExpr` здесь строка числа, а не доказательство динамической формулы. Пользовательские заметки ресурса в снимке сохраняются, но `buildLssResourceBundle()` записывает в лист `notes:""` — возможна потеря заметок при переносе в LSS. Узлы из группы `features` код добавляет в текст `traits`; поэтому нужно проверять реальную ссылку, а не предполагать, что узел всегда лежит в `text[location]`.

Остальные поля:

| Поле | Тип / образец | Назначение |
|---|---|---|
| `bonuses` | array, `[]` | Пользовательские модификаторы из `state.customBonuses` |
| `bonusesSkills`, `bonusesStats` | object, `{}` | Резервные поля; непустая структура не установлена |
| `conditions` | array, `[]` | Состояния; формат элементов не установлен |
| `wizardStep` | string, `"initial"` | Шаг мастера интерфейса, не класс «Волшебник» |
| `isDefault` | boolean, `true` | Служебный флаг шаблона |
| `inspiration` | boolean, `false` | Вдохновение героя; **отдельно** от счётчика Бардовского вдохновения |
| `weapons` | object, `{}` | Резервная структура; строки атак находятся в `weaponsList` |

Непустой `bonuses[]` код генерирует так: `{id:string,label:string,target:string,expr:string,source:{kind:"user"},mode:"add",priority:20,kind:"modifier"}`. При расчёте внешним потребителем важно не применить бонус повторно к уже скорректированным данным.

## 7. Сопоставление конкретного персонажа и ограничения правил

| Проверка | Результат |
|---|---|
| Имя, класс, уровень, вид и предыстория между слоями | Наэстриель, Бард 2, Ченжлинг, Шарлатан — согласованы |
| Исходные характеристики | Массив значений `8,14,13,10,12,15` — перестановка стандартного набора |
| Бонусы предыстории | `CON +2`, `DEX +1`; в локальном справочнике Шарлатану разрешены DEX/CON/CHA |
| Итоговые характеристики | `8,15,15,10,12,15` совпадают в `state.finalAbilities` и `sheet.stats` |
| Модификаторы STR/DEX/CON/INT/WIS/CHA | `−1,+2,+2,0,+1,+2` |
| Владения и компетентность | 10 разных навыков, компетентность в Выживании и Убеждении; согласованы с выбором формы |
| Спасброски | Ловкость и Харизма: итоговые +4 и +4; остальные −1,+2,0,+1 для STR/CON/INT/WIS соответственно |
| Пассивное Восприятие | Расчётное 13 (`10+1+2`); отдельного поля в образце нет |
| Хиты, КД, инициатива | 17, 13, +2 — согласованы с базовыми расчётами |
| Магия | 2 заговора, 5 подготовленных, 3 ячейки 1-го уровня, Сл 12, атака +4 |
| Подкласс | Пуст; для барда 2-го уровня по 2024 это ожидаемо |
| Бардовское вдохновение | 2 использования, к6, долгий отдых; числовой ресурс и текст согласованы |

Правило повышения характеристик от предыстории +2/+1 или +1/+1/+1 соответствует [созданию персонажа 2024](https://www.dndbeyond.com/sources/dnd/br-2024/creating-a-character). Применять сверху ещё и расовые прибавки старой редакции без специального основания нельзя. Режим `best` — рекомендация конструктора, а не отдельный метод из PHB.

**Границы подтверждения:** Ченжлинг и `animate-skull` присутствуют в расширенном каталоге HTML. Их конкретный книжный источник, версия и допустимость для кампании не зафиксированы в JSON. В частности, текст перевоплощения Ченжлинга содержит преимущество на проверки Харизмы; переносить это как общее правило PHB или подтверждённую особенность любого Ченжлинга нельзя. Требуется ссылка на используемую публикацию/решение ведущего. Метка `lssSource` в каталоге указывает на базу карточек, а не на первоисточник правил.

Различия 2014/2024 существенны: в 2024 иначе устроено происхождение, компетентность барда доступна на 2-м уровне, изменены формулировки классовых способностей. Поэтому две компетентности в этом листе не следует объявлять ошибкой на основании PHB 2014. JSON хранит только выбранную редакцию, а не историю миграции и не точное издание каждого источника.

## 8. Рекомендуемые проверки потребителя

Это рекомендуемый контракт интеграции, а не заявление, что HTML реализует строгую схему валидации.

1. Разобрать внешний JSON; убедиться, что это объект `jsonType:"character"`, `version:"2"`, а `data` — строка с корректным объектом `sheet`. Проверить `sheet.jsonType`.
2. Проверить редакции и типы; для данного профиля ожидать `2024`. Незнакомую версию не переинтерпретировать молча.
3. Проверить все шесть характеристик, 18 ключей навыков, числовой уровень 1–20 после преобразования строкового поля формы. На этапе создания применяются ограничения выбранного метода и источников; не ограничивать все возможные игровые характеристики диапазоном 8–15.
4. Сопоставить имя, класс, уровень, вид, предысторию и итоговые характеристики между `fields`, `state` и `sheet`. Расхождение — предупреждение о рассинхронизации, а не повод молча выбрать случайную копию.
5. Для обычного персонажа без специальных исключений проверить `final = base + backgroundBonuses`; при чертах и классовых прибавках учесть дополнительные источники отдельно. Проверить PB, Сл магии, атаку, хиты, КД с учётом исключений и экипировки.
6. Проверить `isProf` навыков как отсутствие/1/2, спасбросков как boolean. Не сводить оба типа к одному флагу. Учесть «Мастера на все руки» отдельно.
7. Разрешить ключи заклинаний через каталог конструктора; сравнить множества внешних ID, учесть текстовый резерв для заклинаний без карточек. Не требовать, чтобы длина `root.spells.prepared` равнялась лимиту подготовленных заклинаний.
8. Для счётчиков проверить `0 ≤ current ≤ resolvedMax`, для ячеек — количество и индексы, для хитов и смертей — допустимость состояния по правилам. Не считать экспортированные нули текущим состоянием после игры.
9. Проверить ссылки `resource.attrs.id` → `resources[id]` и совпадение внутренних ID. ID непрозрачны, могут изменяться между экспортами; не использовать их как постоянный ID персонажа.
10. Сохранить неизвестные поля и узлы форматированного текста при преобразовании. Различать пустой блок и отсутствие блока. Не исполнять содержимое заметок и строковых выражений как код.
